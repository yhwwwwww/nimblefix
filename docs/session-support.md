# NimbleFIX Support Matrix

**English** | [简体中文](session-support.zh-CN.md)

This document defines the supported protocol, runtime, storage, and operational boundaries of NimbleFIX.

> Related docs: [User Guide](user-guide.md) · [Architecture](architecture.md) · [Benchmarks](benchmarks.md)

## Capability & Boundary Matrix

| Area | Supported Behavior | Explicit Boundary |
| :--- | :--- | :--- |
| **3-Layer Packaging** | `NimbleFIX::nimblefix_core` (`DirectInitiator`, `DirectSendQueue`, telemetry, replay), `NimbleFIX::nimblefix_core_tls` (+ OpenSSL 3 `DirectTlsTransport`), `NimbleFIX::nimblefix` (`Engine`, `ShardedEngine`, `IoBackend`, Acceptor); optional `nimblefix` CLI | Rebuild dependent binaries when upgrading; no C++ ABI stability guarantee. |
| **Transport Versions** | `FIX.4.2`, `FIX.4.3`, `FIX.4.4`, `FIXT.1.1` (FIXT Logon validates configured `DefaultApplVerID`) | Numeric IPv4/IPv6 endpoints. Application schema must match configured session. `FIXT.1.1` is session transport; `FIX50SP2` supplies its application dictionary. |
| **Standard & Custom Schemas** | Full `FIX42`, `FIX43`, `FIX44`, `FIXT11`, `FIX50SP2` XML codegen (`nimblefix-schema-gen`); `--messages` subset pruning & `--from-fix-log` log-driven pruning (SOH, pipe `\|`, `.nfxj`); generated `switch(tag)` validator + O(1) `ParsedFieldIndex`; scalar types, enums, components, nested repeating groups, binary `DATA` length pairs; arbitrary custom tags across `1..999,999,999` | Metadata validates dictionary structure and types; venue-specific business rules belong to the application. |
| **Message Encoders & Views** | Streaming `StreamWriter` (`encode_stream` / `send_stream` / `enqueue_stream` / `try_push_stream`) with `if`/`for`, `std::optional`, dynamic `w.header()`, auto `DATA`/`LENGTH` pairs, and nested groups; `Fixed<ByteCap, fix::field::...>`; untyped `nf::message<"D">()` & `DynamicMessage`; zero-copy `FlatMessageView::is<M>()/as<M>()` | Views and `SessionContext` are valid for one callback only — copy values to retain them. Session-managed tags (`8/9/35/49/56/34/52/43/122/369/10`) are managed by the engine; per-message dynamic header tags (`50/57/142/115/128/...`) go through `w.header()` before body fields. |
| **Validation** | Structure, required fields, strict mode; dictionary enums, exact `Decimal` / integer / UTC timestamp representations, repeating group boundaries; per-session schema override (`SessionSettings::use_schema`) for heterogeneous multi-schema engines; per-session `UnexpectedFieldPolicy` (`reject`, `ignore_with_metric`, `passthrough`); optional per-session `verify_checksum = false` bypass for trusted internal links (`true` by default) | Raw flat mode (`FlatSchema`) performs framing/checksum checks and leaves business validation to the application unless a per-session schema is bound. Even with `verify_checksum = false`, `10=ddd<SOH>` framing syntax is enforced. |
| **`DirectInitiator`** | Single-session initiator (`send_stream`, same-thread `enqueue_stream+flush` via `sendmsg`, 2-thread lock-free SPSC `DirectSendQueue` + `drain`); ordered / round-robin multi-endpoint failover (`endpoints` + `ConnectionStrategy`); full FIX session state machine, segmented mmap journal, restart recovery & GapFill/Replay; optional `DirectTlsTransport` | Single initiator session per instance; caller drives `poll_once()` / `drain()` / `reconnect_if_due()` / `poll_maintenance()` on the I/O owner thread. |
| **`Engine`, `ShardedEngine` & `IoBackend`** | Multi-session initiator/acceptor runtime (`Engine`) and multi-core sharded reactor (`ShardedEngine<Schema, Policy>`) with single-port Logon handoff, static session-to-shard pinning, Linux CPU core affinity (`cpu_core` / `cpu_cores`), pluggable `IoBackend` (`epoll`, `busy_poll`, optional Linux `io_uring`), and `IdleStrategy` (`sleep`, `busy_spin`, `hybrid_backoff`); `Inline` and `Queued` policies; multi-endpoint initiator failover | Strict single-writer per session. Callbacks on `ShardedEngine` run concurrently across different shards and sequentially per session. `io_uring` is opt-in (`--io_uring=y` / `-DNIMBLEFIX_ENABLE_IO_URING=ON`); requesting it when disabled returns `ErrorCode::unsupported`. |
| **Cross-Thread Sending** | `DirectInitiator`: lock-free SPSC `DirectSendQueue`. `Engine`/`ShardedEngine`: MPSC `Sender` and lock-free SPSC `ProducerLane` | Same-producer ordering only; no global total order across independent producer threads or sessions. Cross-thread misuse of `ProducerLane` returns `wrong_thread`. |
| **Logon & Authentication** | Initiator/acceptor, configured CompIDs/version, positive `HeartBtInt`, `EncryptMethod=0`, credentials/custom fields, callback authentication | Acceptor authenticates before opening a session journal. Credentials require TLS by default unless explicitly opted out (`require_tls=false`). Non-recovery Logon secrets are scrubbed from persisted payloads. |
| **Heartbeat & TestRequest** | Timer Heartbeat, matching `TestReqID`, finite liveness and write-stall deadlines | `Inline` callbacks must finish promptly; user C++ code cannot be forcibly preempted. |
| **SendingTime** | Configurable per-session `timestamp_precision`: milliseconds (`ms`, default), microseconds (`us`), or nanoseconds (`ns`); UTC calendar validation; default `Engine` skew tolerance 120 s; Session Reject then Logout on excessive skew | Host clock synchronization (NTP/PTP) is an operator responsibility. |
| **Gaps & Replay** | `ResendRequest`, `GapFill`, forward `SequenceReset` reset mode, original-sequence business replay with `PossDupFlag=Y` and `OrigSendingTime` | Replay never splits a partially written frame. Required history pruned beyond retention returns `history_unavailable` instead of fabricating a business `GapFill`. |
| **Sequence Epochs & Admin Controls** | Explicit allowed Logon reset (`141=Y`), audited epoch record, opt-in EOD/BOD `reset_on_schedule_boundary`; thread-safe runtime `request_logout`, `request_reconnect`, one-shot `request_sequence_reset`, and offline durable `adjust_sequences` (with GapFill replay across adjusted ranges) across `Engine`, `ShardedEngine`, `SessionDriver`, and `DirectInitiator` | Default preserves sequence state across reconnects. `adjust_sequences` requires the session to be disconnected; lowering sequences requires `allow_sequence_reset`. Pending input/read leases prevent unsafe reset. |
| **FIX 369 (`LastMsgSeqNumProcessed`)** | Emits highest contiguous business-completed inbound sequence; validates peer progress; feeds retention floor | Appended-but-unfinished inbound messages are never acknowledged via tag `369` until their callback and dependent replies commit. |
| **Logout & Rejects** | Local, peer, and simultaneous Logout with write-before-close and finite shutdown deadline; structured Session Reject (`35=3`) for schema/type errors | Counterparty-specific `BusinessMessageReject` (`35=j`) rules remain application policy. |
| **Segmented mmap Journal** | Pre-allocated segmented `MAP_SHARED` mmap journal with hardware SSE4.2 CRC32C, zero-copy `reserve()`/`commit()`, atomic `.tmp` + `rename` segment creation, index/checkpoint rebuild, rotation, off-hot-path `poll_maintenance()`, in-process lease-protected `JournalReader`, and cross-process lock-free read-only SPMC `JournalTailer` (`O_RDONLY`/`PROT_READ`, zero writer overhead) | No in-memory-only store mode. Segment indexes and `RecordId`s are monotonic and never reused within a store. Full storage fails closed rather than overwriting required replay history. Cross-process `JournalTailer` never blocks the writer; lagging past pruned segments returns `reader_expired` / `history_unavailable`. |
| **Recovery & Confirmation** | Append-before-TX and append-before-callback; crash recovery re-delivers unfinished inbound records (`is_recovery == true`) and reuses previously committed dependent replies | Confirmation level `appended` covers same-host process crashes (`SIGKILL`/abort) while OS/filesystem remain healthy. No per-message `fsync`/`msync` or power-loss guarantee. At-least-once delivery requires idempotent external side effects. |
| **Receipts (`Engine`)** | `accepted`, `appended`, `written`, `failed`, `expired` with bounded circular retention | `written` means the local socket/TLS transport accepted bytes; counterparty receipt requires application-level confirmation (e.g. `ExecutionReport`). |
| **TLS** | Optional OpenSSL 3 (`DirectTlsTransport` & `Engine`), TLS 1.2/1.3, CA + SAN hostname/IP verification, optional mTLS, nonblocking `WANT_READ`/`WANT_WRITE`, `TlsContext` reuse on reconnect | Interactive passphrase-encrypted private keys are not supported. Verification failures close immediately with no plaintext fallback. |
| **Identity, Scheduling & Sockets** | Persistent store identity = transport version + oriented CompIDs + optional qualifier; explicit UTC weekday/time session windows including overnight spans and opt-in `reset_on_schedule_boundary`; `SocketOptions` for numeric local source IP/port binding, `TCP_QUICKACK`, `SO_SNDBUF`/`SO_RCVBUF`, and best-effort `SO_BUSY_POLL` | Session display names and socket ports are not part of persistent identity. No DST/timezone translation; `reset_on_schedule_boundary` is off by default and requires `enabled` + `allow_sequence_reset`. |
| **Out-of-Band Telemetry** | Opt-in `telemetry_path` (`.nfxt` `MAP_SHARED`) & `telemetry_stage_probes` across `DirectInitiator`, `Engine`, and `ShardedEngine`; 433-bucket single-writer HDR nanosecond histograms (`read`/`parse`/`validate`/`journal`/`write`, `p50/p90/p99/p99.9/p99.99`); read-only `TelemetryReader` + `nimblefix telemetry` | Disabled by default (zero overhead when unused). Single-writer per session guarantees zero locks, zero malloc, and zero fsync on the hot path. |
| **Historical Replay** | `<nimblefix/replay.hpp>` (`JournalReplayer::replay` / `replay_to_tcp`) & `nimblefix replay`; lock-free cross-process `JournalTailer` for path-based live or offline `.nfxj` replay (without acquiring `LOCK_EX`) plus in-process lease-protected `JournalReader` overload; direction/sequence/epoch/admin filtering, `ReplayOptions::wire_hints` for custom `DATA`/`LENGTH` pairs, full-speed / original / scaled pacing, callback sink or TCP streaming | Replays committed FIX frames verbatim. |
| **Manual Event Loop** | `Engine::start()` + `poll_once(max_wait_ms)` on a caller-owned thread; `DirectInitiator::poll_once()` / `drain()` on caller thread; thread-safe `request_stop()` | Single lifecycle per `Engine` instance; recreate with the same storage directory for a subsequent run. |

## Default Resource & Storage Limits

| Parameter | Default | Notes |
| :--- | ---: | :--- |
| Heartbeat interval | 30 s | Configurable per session |
| Connect / Logon / TLS handshake timeout | 10 s | Bounded failure on stall |
| Reconnect backoff | 250 ms | Automatic reconnect on initiator |
| Write stall / pending age / read pause / delivery age | 30 s | `max_pending_age_ms=0` disables outbound age expiry |
| Logout completion deadline | 5 s | Bounded shutdown |
| Maximum FIX frame size | 64 KiB | Admin traffic reserves 8 TX slots + 2 max-frame byte budgets |
| `Engine` capacity | 64 sessions, 32 pending sockets | 256 TX msgs / 4 MiB, 128 pending input msgs / 4 MiB |
| `Engine` Sender / Receipts / Queued workers | 256 Sender cmds / 4 MiB, 1,024 receipts, 2 workers (128 callbacks / 4 MiB) | Configurable in `EngineConfig` |
| Journal budget (per session) | 16 MiB total, 1 MiB segments, 65,536 indexed records, 8,192 retained outbound msgs | Epoch audit reserves 1 MiB when budget allows; up to 65,535 segments and 1,024 audited resets per store |
| Independent journal readers | 16 reader slots, 65,536-record max lag | Lease-protected against premature segment pruning |
